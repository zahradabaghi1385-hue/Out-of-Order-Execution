مشکل اجرای ترتیبیThe problem with in-order execution

lw  x1, 0(x2)
add x3, x1, x4
sub x5, x6, x7
and x8, x9, x10
  • lw: دریافت داده از حافظهlw: fetches data from memory
  • add: وابسته به نتیجهٔ lwadd: depends on the result of lw
  • sub و and: مستقل از lwsub and and: independent of lw

مشکل: انتظار یک دستور می‌تواند مانع اجرای دستورهای مستقل شود.Problem: one instruction waiting can block independent instructions from running.

ایدهٔ اصلی OOOThe main idea of OOO

  • دریافت دستورها به ترتیب برنامهFetch instructions in program order
  • اجرای دستورهای آماده، مستقل از ترتیب اولیهExecute ready instructions, regardless of the original order
  • حفظ وابستگی‌های واقعی میان دستورهاPreserve the true dependencies between instructions
  • تأیید نهایی نتایج به ترتیب برنامهFinalize (commit) the results in program order

هدف: کاهش زمان انتظار و استفادهٔ بهتر از واحدهای اجراییGoal: less waiting time and better use of the execution units

جدول روند کلی اجرای OOOOverview of the OOO execution flow

تفاوت ترتیب اجرا و ترتیب برنامهExecution order vs. program order

Program Orderترتیب اصلی دستورها در برنامهThe original order of the instructions in the program
Execution Orderترتیبی که دستورها واقعاً اجرا می‌شوندThe order in which the instructions actually execute
Commit Orderترتیب تأیید نهایی نتایجThe order in which the results are finalized

در OOO، ترتیب اجرا می‌تواند تغییر کند؛ اما ترتیب Commit حفظ می‌شود.In OOO the execution order can change, but the Commit order is preserved.

وابستگی دستورهاInstruction dependencies

RAW · Read After Writeوابستگی واقعی داده؛ دستور بعدی به نتیجهٔ قبلی نیاز دارد.True data dependency; the next instruction needs the result of the previous one.
WAR · Write After Readوابستگی نامی؛ نوشتن دستور بعدی ممکن است با خواندن قبلی تداخل داشته باشد.Name dependency; the next instruction's write may clash with the previous instruction's read.
WAW · Write After Writeوابستگی نامی؛ چند دستور در یک نام ثبات می‌نویسند.Name dependency; several instructions write to the same register name.

Register Renaming وابستگی‌های نامی را برطرف می‌کند، اما وابستگی واقعی RAW را حفظ می‌کند.Register Renaming removes the name dependencies, but keeps the true RAW dependency.

تغییر نام ثبات‌ها (Register Renaming)Register Renaming

قبل از تغییر نامBefore renaming
I1: add x1, x2, x3
I2: sub x4, x1, x5
I3: add x1, x6, x7
بعد از تغییر نامAfter renaming
I1: add p10, x2, x3
I2: sub p11, p10, x5
I3: add p12, x6, x7
  • x1: نام منطقی ثباتx1: a logical register name
  • p10، p11، p12: ثبات‌های فیزیکیp10, p11, p12: physical registers
  • وابستگی واقعی I2 به نتیجهٔ I1 حفظ می‌شود.The true dependency of I2 on the result of I1 is preserved.
  • I3 دیگر برای نوشتن نتیجه مجبور نیست منتظر I1 بماند.I3 no longer has to wait for I1 in order to write its result.

مزایای اجرای خارج از ترتیبBenefits of out-of-order execution

  • کاهش زمان بیکاری واحدهای اجراییLess idle time for the execution units
  • استفاده از زمان انتظار حافظه برای اجرای کارهای مستقلUsing memory wait time to run independent work
  • افزایش بهره‌برداری از منابع پردازندهBetter utilization of the processor's resources
  • بهبود عملکرد بسیاری از برنامه‌های واقعیBetter performance for many real programs

هزینه‌ها و محدودیت‌هاCosts and limitations

  • طراحی سخت‌افزاری پیچیده‌ترMore complex hardware design
  • مصرف انرژی و فضای تراشهٔ بیشترMore power consumption and more chip area
  • محدودیت ناشی از وابستگی‌های واقعیA limit imposed by true dependencies
  • احتمال دورریختن کارهای حدسی پس از پیش‌بینی اشتباهSpeculative work may be thrown away after a wrong prediction

OOO سرعت را افزایش می‌دهد، اما تضمین نمی‌کند همهٔ برنامه‌ها سریع‌تر اجرا شوند.OOO increases speed, but it does not guarantee that every program runs faster.

OOO و امنیت پردازندهOOO and processor security

Speculative Execution — اجرای حدسیSpeculative Execution

  • اجرای دستورها بر اساس پیش‌بینی پردازندهExecuting instructions based on the processor's prediction
  • کنارگذاشتن نتایج معماری در صورت پیش‌بینی اشتباهDiscarding the architectural results if the prediction was wrong
  • امکان باقی‌ماندن برخی آثار جانبی ریزمعماری، مانند تغییر وضعیت کشSome microarchitectural side effects may remain, such as a change in cache state

پرسشQuestion

فرض کنید دستورهای زیر به ترتیب در برنامه قرار دارند:Suppose the following instructions appear in this order in a program:

I1: ADD R1, R2, R3
I2: SUB R4, R5, R6
I3: ADD R7, R1, R4

با توجه به مفهوم Out-of-Order Execution پاسخ دهید:Using the concept of Out-of-Order Execution, answer:

  • ۱. آیا دستور I2 می‌تواند قبل از I1 اجرا شود؟ چرا؟1. Can I2 execute before I1? Why?
  • ۲. آیا دستور I3 می‌تواند قبل از هر دو دستور I1 و I2 اجرا شود؟2. Can I3 execute before both I1 and I2?
  • ۳. آیا اجرای خارج از ترتیب به معنی تغییر ترتیب نهایی دستورهاست؟3. Does out-of-order execution mean the final order of the instructions changes?

پاسخ پرسشAnswer

  • ۱. بله. دستور I2 به نتیجهٔ I1 وابسته نیست؛ بنابراین اگر منابع پردازنده آماده باشند، می‌تواند زودتر اجرا شود.1. Yes. I2 does not depend on the result of I1, so if the processor's resources are available, it can execute earlier.
  • ۲. خیر. دستور I3 به نتیجهٔ هر دو دستور I1 و I2 وابسته است؛ چون از مقادیر R1 و R4 استفاده می‌کند. پس باید منتظر آماده‌شدن نتایج آن‌ها بماند.2. No. I3 depends on the results of both I1 and I2, because it uses the values of R1 and R4. So it must wait until their results are ready.
  • ۳. خیر. ترتیب اجرا می‌تواند تغییر کند، اما در پردازنده‌های دارای سازوکار نهایی‌سازی مرتب، دستورها به ترتیب اصلی برنامه Commit می‌شوند.3. No. The execution order can change, but in processors with an in-order finalization mechanism, instructions are committed in the original program order.

نکتهٔ کلیدی: پردازنده دستورهای مستقل را زودتر اجرا می‌کند، اما وابستگی‌های واقعی را نادیده نمی‌گیرد.Key point: the processor runs independent instructions earlier, but never ignores true dependencies.
